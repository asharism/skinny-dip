## What Skinny Dip is

A SwiftUI multiplatform Markdown scratchpad (macOS 26 / iOS 26 / iPadOS 26) with live preview and **Copy as Rich Text (⌘C)**: write Markdown, paste clean rich text into Outlook, Word, Gmail, Teams. Clipboard fidelity is the hard part and the reason the app exists. Success = the user stops opening VS Code to preview-and-copy. Mac ships first; iOS/iPadOS is designed in but shipped later.

## Commands

```sh
# Core logic tests — fast, no simulator. This is the main TDD loop.
swift test --package-path Packages/MarkdownCore
swift test --package-path Packages/MarkdownCore --filter GoldenTests

# Generate the Xcode project (needs `brew install xcodegen`)
xcodegen generate

# Build the app and run the scheme's tests (currently the MarkdownCore tests)
xcodebuild build -scheme SkinnyDip -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/xcode
xcodebuild test -scheme SkinnyDip -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/xcode
```

Golden tests: add a pair `Packages/MarkdownCore/Tests/MarkdownCoreTests/Golden/<name>.md` + `<name>.html`; `GoldenTests` picks it up automatically. Trailing newlines in the `.html` are ignored.

## Architecture

```
SkinnyDip/
  App/        SwiftUI shell, DocumentGroup, commands, settings
  Platform/   EditorView+Mac.swift, EditorView+iOS.swift, Clipboard+*.swift
  Resources/  preview.html, theme.css, highlight.min.js
Packages/MarkdownCore/
  Sources/    Parser actor, HTML renderer, document model
  Tests/      golden files: input.md -> expected.html
```

- **All logic lives in `MarkdownCore`** (pure Swift, no UI). The app target stays thin. Only the editor wrapper and clipboard code differ per platform.
- **Parser:** Apple `swift-markdown` (cmark-gfm). A parser `actor` renders off-main; edits trigger a cancellable `Task` debounced 150–250 ms.
- **One renderer, two consumers.** `MarkdownCore` emits bare semantic HTML only (`h1–h6`, `p`, `br`, `ul/ol/li`, `strong/em`, `a`, `img`, `blockquote`, `table`, `pre/code`, `hr`) — never `class`, `style`, `font` or color attributes, and never an inliner (ADR-0001).
  - **Preview** wraps that HTML in theme CSS. Load `preview.html` once into SwiftUI `WebView`/`WebPage`, then push new bodies via JS `render(html)`. Never reload per keystroke (it flashes and loses scroll). highlight.js is bundled locally; no network.
  - **Clipboard** gets it bare, so the paste takes on the destination's fonts and heading styles. Copy is pure Swift, no JS.
- **Pasteboard flavors:** `public.html` (minimal `<html><body>`, UTF-8) + `public.utf8-plain-text` (the Markdown). **No RTF** — `NSAttributedString(html:)` bakes in fonts.
- **Commands:** ⌘C Copy as Rich Text (both flavors), ⌘⇧C Copy as Markdown (plain only), ⌥⌘C Copy as HTML. Pasting our own copy back into Skinny Dip uses the Markdown flavor. ⌘V Paste as Markdown (P4) converts rich text from other apps; ⌥⇧⌘V pastes plain.
- **Selection copy** (editor only) parses the selected text as a standalone document plus the full document's link reference definitions; the plain-text flavor is the exact selection. ⌘C in the preview copies the whole document via Copy as Rich Text, never WebKit's styled copy.
- **Rendering rules** (defaults, settings can toggle): heading demotion by one level (`h6` stays `h6`); `border="1"` on tables; every newline is `<br>`; raw HTML escaped; `<img>` only for `http(s)` URLs, local paths render as alt text; task lists as ☐/☑ characters.
- **Markdown Source is the truth** (ADR-0002): the app never rewrites text the user didn't type. No WYSIWYG.
- **Editor:** CodeMirror 6 in a `WKWebView` (ADR-0003), behind an `EditorView` abstraction (`NSViewRepresentable` on Mac). The editor reports text and selection to Swift; copy stays pure Swift. We own the Swift↔JS bridge (undo and edited state, Select All, Edit menu); MarkEdit (MIT) is the reference. The JS bundle is built with esbuild and checked in so the app builds without Node. Kept evaluation apps for all three candidates live in `Spikes/Editors/`; re-run them after macOS or WebKit updates. iOS editor (P6) is open: CodeMirror also runs on iOS.
- **Layout:** no `HSplitView` (macOS-only). Use a shared `SplitPane` (HStack + drag handle) on Mac/iPad and an editor/preview toggle on iPhone.
- **UI Shell** (ADR-0005, `docs/design/ui-shell.md`): one Tab = one `DocumentGroup` document; the Tab strip is drawn by us over the native window tab group (`NSWindow.tabGroup`), never a hand-rolled document manager. Editor and Preview are two floating Cards on an opaque, theme-tinted window. Themes are JSON files in `SkinnyDip/Resources/themes/` (Rex's terminal token shape); `Theme.resolve()` in MarkdownCore turns them into roles. Themes never reach the clipboard.
- **Scroll sync** (ADR-0006): one-way, Editor → Preview, through `data-source-line` anchors that only `PreviewHTML` emits.
- **Documents:** `DocumentGroup` + `FileDocument` with UTType `net.daringfireball.markdown`. Never show a save prompt (ADR-0007): saved files autosave in place; never-saved documents are Scratch Documents stored under Application Support, restored on launch with their undo history; closing one moves it to Recently Closed.
- Wrap first-generation 26 APIs (`WebView`, `TextEditor`) behind protocols so they can fall back to `WKWebView` / `UITextView`.

## Agent ownership

**Agents own building the app end-to-end.** Implement features, fix bugs, run `xcodegen`, `xcodebuild`, and tests, rebuild the editor bundle when JS changes, and **launch the app locally** when a change needs review. Do not hand work back with “you verify,” “run this yourself,” or “ready for human” as the next step. If something needs eyes on UI (paste matrix, Writing Tools, dictation), **open the built app and exercise it**; only ask the user when a product decision is genuinely ambiguous or blocked on credentials or hardware you cannot use.

Issue labels like `ready-for-human` describe repo triage, not permission to stop implementing. Prefer `ready-for-agent` work and drive it to green builds without delegating execution.

## Working agreements

- **TDD:** each phase starts with failing golden-file tests (`.md` → expected `.html`) in `MarkdownCore/Tests`, then code until green. One PR-sized story per session. Draft failing tests, implement, and iterate until tests and build pass—without waiting for human approval of the test list first.
- **MVP scope is the contract.** Out for now: two-way scroll sync, line numbers, theme import or editing, window translucency, plugins, math/Mermaid, PDF/DOCX export, iCloud, sidebar, App Store. A new feature needs a paste-workflow reason.
- The paste matrix is tested by hand every release from `docs/paste-matrix/fixture.md`, results logged in `docs/paste-matrix/results.md`. Tier 1 (blocks release, wins ties): new Outlook, Outlook for Mac, Teams. Tier 2 (fix when cheap): Word, Gmail web, Apple Mail, Google Docs. Keep the HTML simple (no flex or grid).
