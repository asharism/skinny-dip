## What Skinny is

The app is **Skinny** (renamed from Skinny Dip). The repo, Xcode target, Swift module and bundle ID `com.hitesh.SkinnyDip` keep the old name on purpose, so the sandbox container and Scratch Documents carry over (ADR-0009).

A SwiftUI multiplatform Markdown scratchpad (macOS 26 / iOS 26 / iPadOS 26) with live preview and **Copy as Rich Text (⌘⇧C)**: write Markdown, paste clean rich text into Outlook, Word, Gmail, Teams. Clipboard fidelity is the hard part and the reason the app exists. Success = the user stops opening VS Code to preview-and-copy. Mac ships first; iOS/iPadOS is designed in but shipped later.

## Commands

```sh
# Core logic tests — fast, no simulator. This is the main TDD loop.
swift test --package-path Packages/MarkdownCore
swift test --package-path Packages/MarkdownCore --filter GoldenTests

# Generate the Xcode project (needs `brew install xcodegen`)
xcodegen generate

# Build the app and run the scheme's tests (MarkdownCoreTests and SkinnyDipTests),
# under a separate bundle ID so the user's Scratch Documents are untouched (see Agent ownership)
xcodebuild build -scheme SkinnyDip -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/agent PRODUCT_BUNDLE_IDENTIFIER=com.hitesh.SkinnyDipAgent
xcodebuild test -scheme SkinnyDip -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/agent PRODUCT_BUNDLE_IDENTIFIER=com.hitesh.SkinnyDipAgent

# Release: test, build, sign, tag vX.Y.Z, publish a GitHub Release + Sparkle appcast (ADR-0009)
scripts/release.sh 0.2.0
scripts/release.sh 0.2.0 --dry-run   # build and sign into dist/, publish nothing
```

The built app is `Skinny.app` (`PRODUCT_NAME`); the scheme is still `SkinnyDip`. Releases are ad-hoc signed until a Developer ID exists. Updates are EdDSA-signed with the Sparkle key in the login keychain, so never regenerate it.

Golden tests: add a pair `Packages/MarkdownCore/Tests/MarkdownCoreTests/Golden/<name>.md` + `<name>.html`; `GoldenTests` picks it up automatically. Trailing newlines in the `.html` are ignored. Paste as Markdown goldens run the other way: `Golden/paste/<name>.html` → `<name>.md` (`PasteGoldenTests`); `capture-*` files are real clipboard HTML from Word, Safari and Chrome, so add Outlook/Teams/Gmail captures the same way.

## Architecture

```
SkinnyDip/
  App/        SwiftUI shell, DocumentGroup, commands, settings
  Platform/   NativeEditorView+Mac.swift, EditorResponder+Mac.swift, PreviewView+Mac.swift, Clipboard+*.swift
  Resources/  preview.html, theme.css, highlight.min.js
Packages/MarkdownCore/
  Sources/    Parser actor, HTML renderer, document model
  Tests/      golden files: input.md -> expected.html
```

- **All logic lives in `MarkdownCore`** (pure Swift, no UI). The app target stays thin. Only the editor wrapper and clipboard code differ per platform.
- **Parser:** Apple `swift-markdown` (cmark-gfm). A parser `actor` renders off-main; edits trigger a cancellable `Task` debounced 150–250 ms.
- **One renderer, two consumers.** `MarkdownCore` emits bare semantic HTML only (`h1–h6`, `p`, `br`, `ul/ol/li`, `strong/em`, `a`, `img`, `blockquote`, `table`, `pre/code`, `hr`) — never `class`, `font`, or color attributes, and never an inliner (ADR-0001). The one `style` exception is the table grid: a 1px solid border so Word and Outlook draw a single line instead of a beveled double rule.
  - **Preview** wraps that HTML in theme CSS. Load `preview.html` once into a `WKWebView` (ADR-0004), then push new bodies via JS `render(html)`. Never reload per keystroke (it flashes and loses scroll). highlight.js is bundled locally; no network.
  - **Clipboard** gets it bare, so the paste takes on the destination's fonts and heading styles. Copy is pure Swift, no JS.
- **Pasteboard flavors:** `public.html` (minimal `<html><body>`, UTF-8) + `public.utf8-plain-text` (the Markdown). **No RTF** — `NSAttributedString(html:)` bakes in fonts.
- **Commands** (ADR-0011): ⌘C is the standard Copy: the selected Markdown, plain text only, and nothing with no selection. ⌘⇧C Copy as Rich Text (both flavors), ⌥⌘C Copy as HTML; both copy the whole document with no selection. Copy as Markdown lives only in the Copy split button's menu, not the Edit menu. Pasting our own copy back into Skinny uses the Markdown flavor. ⌘V Paste as Markdown (P4) converts rich text from other apps; ⌥⇧⌘V pastes plain.
- **Selection copy** parses the selected text as a standalone document plus the full document's link reference definitions; the plain-text flavor is the exact selection. A Preview selection maps back to the Markdown Source of the top-level blocks it touches (`PreviewSelection`, via `data-source-line`) and copies the same way, with the same shortcuts as the Editor. Never WebKit's styled copy.
- **Rendering rules** (defaults, settings can toggle): heading demotion by one level (`h6` stays `h6`); tables get a single 1px solid grid with cell padding (`border="1"`, `cellspacing="0"`, `cellpadding="6"`, and `border:1px solid #000` on the table and each cell); every newline is `<br>`; raw HTML escaped; `<img>` only for `http(s)` URLs, local paths render as alt text; task lists as ☐/☑ characters.
- **Markdown Source is the truth** (ADR-0002): the app never rewrites text the user didn't type. No WYSIWYG.
- **Editor:** a native `NSTextView` (TextKit 2), the only editor (ADR-0010; the CodeMirror 6 editor of ADR-0003 was removed). `EditorHost` builds `NativeEditorView`; menus, paste and Writing Tools reach it through `EditorResponder`, and its Markdown highlighting comes from `MarkdownCore.highlightSpans`. Spell check, autocorrect, dictation and Writing Tools come from AppKit. Kept evaluation apps for the original three candidates live in `Spikes/Editors/`.
- **Layout:** no `HSplitView` (macOS-only). Use a shared `SplitPane` (HStack + drag handle) on Mac/iPad and an editor/preview toggle on iPhone.
- **UI Shell** (ADR-0005, `docs/design/ui-shell.md`): one Tab = one `DocumentGroup` document; the Tab strip is drawn by us over the native window tab group (`NSWindow.tabGroup`), never a hand-rolled document manager. Editor and Preview are two opaque floating Cards on the Chrome, which is theme-tinted glass (behind-window blur under the gradient at 62%; opaque with Reduce Transparency). Themes are JSON files in `SkinnyDip/Resources/themes/` (Rex's terminal token shape); `Theme.resolve()` in MarkdownCore turns them into roles. Themes never reach the clipboard.
- **Scroll sync** (ADR-0006): one-way, Editor → Preview, through `data-source-line` anchors that only `PreviewHTML` emits.
- **Documents:** `DocumentGroup` + `FileDocument` with UTType `net.daringfireball.markdown`. Never show a save prompt (ADR-0007): saved files autosave in place; never-saved documents are Scratch Documents stored under Application Support, restored on launch (text and placement; undo history lives in memory only); closing one moves it to Recently Closed.
- **Distribution** (ADR-0009): GitHub Releases + Sparkle 2. `SUFeedURL` is `releases/latest/download/appcast.xml`; Debug builds don't start the updater. Keep the Mac rpath `@executable_path/../Frameworks` in `project.yml` or Sparkle fails to load at launch.
- Wrap first-generation 26 SwiftUI APIs (today, the iOS `TextEditor` in `ContentView`) behind protocols so they can fall back to `UITextView`.

## Agent ownership

**Agents own building the app end-to-end.** Implement features, fix bugs, run `xcodegen`, `xcodebuild`, and tests, and **launch the app locally** when a change needs review. Before asking anyone to verify editor behavior, run `xcodebuild test … -derivedDataPath .build/agent PRODUCT_BUNDLE_IDENTIFIER=com.hitesh.SkinnyDipAgent -only-testing:SkinnyDipTests/NativeEditorTests` (the native editor in a real window: text and selection, paste, copy, undo, highlighting, gutter). Do not hand work back with “you verify” as the default next step. If automation cannot cover something (Writing Tools sheet UI, live dictation audio, paste matrix), exercise the built app yourself first; only ask the user for product decisions or blocked credentials/hardware.

**Run your builds under a separate bundle ID.** The user usually has `/Applications/Skinny.app` open with real Scratch Documents in the sandbox container for `com.hitesh.SkinnyDip`. A Debug build or test host with that bundle ID shares the container and can overwrite them. So build, launch and test with `-derivedDataPath .build/agent PRODUCT_BUNDLE_IDENTIFIER=com.hitesh.SkinnyDipAgent`, which gets its own container (scratch files, defaults, saved state). `scripts/soak.sh` already does this.

Driving that build from the terminal:
- **Screenshots:** launch with `SKINNYDIP_SNAPSHOT=<path>.png`, using a path inside `~/Library/Containers/com.hitesh.SkinnyDipAgent/Data/tmp/`, since the sandbox can't see other temp folders. Create `<path>.png.trigger` to capture the key window, or `<path>.png.layout` to dump windows, Tabs and the strip to `<path>.png.layout.txt` (`DebugSnapshot+Mac.swift`). Screen capture doesn't work, and the snapshot timer doesn't fire mid-drag.
- **Input:** synthetic CGEvent mouse drags reach the app. Synthetic keyboard input (osascript keystroke, `CGEvent.postToPid`) does not, so drive typing from inside the app (`DebugSoak+Mac.swift`, #62).
- **Menus:** two processes are named Skinny, so target osascript menu clicks by `unix id`.

Issue labels like `ready-for-human` describe repo triage, not permission to stop implementing. Prefer `ready-for-agent` work and drive it to green builds without delegating execution.

## Working agreements

- **TDD:** each phase starts with failing golden-file tests (`.md` → expected `.html`) in `MarkdownCore/Tests`, then code until green. One PR-sized story per session. Draft failing tests, implement, and iterate until tests and build pass—without waiting for human approval of the test list first.
- **MVP scope is the contract.** Out for now: custom themes, plugins, math/Mermaid, PDF/DOCX export, iCloud, sidebar, App Store. A new feature needs a paste-workflow reason.
- The paste matrix is tested by hand every release from `docs/paste-matrix/fixture.md`, results logged in `docs/paste-matrix/results.md`. Tier 1 (blocks release, wins ties): new Outlook, Outlook for Mac, Teams. Tier 2 (fix when cheap): Word, Gmail web, Apple Mail, Google Docs. Keep the HTML simple (no flex or grid).
